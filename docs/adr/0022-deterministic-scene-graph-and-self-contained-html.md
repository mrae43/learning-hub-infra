# 0022 — Deterministic Scene Graph and Self-Contained HTML Rendering

## Status

Accepted

## Context

`ADR-0020`, `ADR-0021`, and the depth-dive redefinition spec define the Depth Dive output as an `interactive_animation` scene graph — a declarative, stateless payload the client renders without further server calls. The scene graph is generated by the LLM in the assembly agent's final turn: `generation_agent.run_generation` prompts the model to emit the full scene graph as JSON (element `type`s, `x`/`y` coordinates, `steps`, and per-element `element_states`), and `parse_animation` validates the result, falling back to `build_fallback_animation` on malformed output.

That design has two costs:

1. **The model owns layout *and* semantics together.** It must invent geometry (where every token and arrow sits in the `viewport` coordinate space) in addition to the conceptual content. The result is non-deterministic — the same passage yields a different layout each call — and the structural JSON (coordinates, IDs, step state) is token spend that carries no explanation value.
2. **The client is deferred to an unspecified "separate UI repo"** (`ADR-0020`), so the scene graph has no renderer in this repository. The only renderer today is an illustrative prototype under `.scratch/`.

Two motivations for change: first, prior experience with freeform generated scene/video output (a third-party service turning structured prompts into second-by-second scenes) produced slop — unvalidated freeform output that is expensive and low quality. Second, the Depth Dive client is being delivered as self-contained HTML through a Claude Code plugin (`ADR-0023`), which changes the delivery edge but not the need for a validated, typed output contract.

## Decision

The `InteractiveAnimation` scene graph remains the output contract; how it is produced changes.

1. **`/dive` keeps returning the scene graph.** `HarnessBResponse` and the `interactive_animation` contract (spec §7) are unchanged. Self-contained HTML is a *render* of the validated scene graph, not a new output type — no change to `SUPPORTED_OUTPUT_TYPE`, the framing agent's routing, or the request contract.

2. **The scene graph becomes template-generated, not LLM-generated.** The LLM stops emitting the scene graph. It instead emits **prose** (the explanatory narration) plus a **bounded semantic spec** (content and relations, no geometry): for a text/code passage, the tokens and their relations (e.g. "token 2 attends to token 4 with weight 0.7"); for image/diagram/table passages, the visual is the carried/rendered asset already produced by the Passage Transform.

3. **A deterministic renderer owns layout and markup.** A new `depth_dive/render/` subpackage runs in two stages, entirely in code:
   - *Semantic spec → scene graph.* Compute geometry from the spec: lay tokens out evenly, derive arrow endpoints and stroke width from relation weights, turn narration into `steps`. This preserves the `InteractiveAnimation` contract — it is simply produced by code rather than by the model.
   - *Scene graph → self-contained HTML.* Emit HTML/CSS/JS where all markup, styling, and the CSS-driven animation (step reveal, prediction reveal, carousel transition) are code-owned. The `.scratch/depth-dive/interactive-animation-contract.html` prototype is promoted as the renderer's starting point.

4. **The LLM's text is escaped data, never markup.** Self-containment and no-external-dependency are properties of the code-owned templates, held *by construction* rather than enforced by a sanitizer or trusted to prompt compliance.

5. **The schema is re-scoped, not frozen.** `SceneElement.x`/`y` become optional layout hints with renderer-computed defaults (layout is renderer-owned). `parse_animation` is re-scoped to parse and validate the bounded semantic spec rather than a full scene graph. `build_fallback_animation` survives as the degraded path — it still yields a valid scene graph when the semantic spec is malformed.

## Consequences

- The LLM generation turn shrinks to prose + a bounded semantic spec: cheaper, no structural-token churn, and the geometry-error class of parse fallback disappears (semantic-spec validation still applies). Determinism now lives in the renderer, which is unit-testable.
- **Tradeoff accepted:** the visual is no longer *arbitrary*. A template can only draw what its SVG is parameterized to draw. The LLM can say "token 2 attends to token 4" but not "place a purple hexagon at (341, 87)." Semantic relations survive; freeform diagrams do not.
- `generation_agent.SYSTEM_PROMPT` is rewritten to request the semantic spec; `_TREATMENT_INSTRUCTIONS` stays (treatment → template mapping). The framing agent is unchanged — its treatment routing is already deterministic.
- `tests/depth_dive/generation/test_generation_agent.py` and the scene-graph tests are re-scoped to semantic-spec parsing plus renderer output; the renderer gets its own test suite mirroring the spec §7 worked example.
- Screen-size independence (spec §7 design constraint) shifts from "the client's job" to "the renderer's job": responsive layout is code responsibility, not model responsibility.
- `ADR-0020`'s "LLM generation turn produces the scene graph" is superseded by this decision; `ADR-0021` (captured-passage model) is unaffected.
